# Qiji 批量下载器

吃管理端「批量下载」页导出的 JSON 清单，把产物并发抓到本地。单文件 exe（约 840KB），无运行时依赖。

## 为什么需要它

服务端生成成功后会把产物转存进对象存储（OSS），拿到永久直链。但**转存失败时**服务端不会整单报废
（上游已经扣过费了），而是回退**上游原链**完成任务 —— 那些产物没有永久直链、也不在资产台账里，
只存在于请求记录。这个工具就是把它们批量捞出来的。

## 两条硬约束（先看这个）

1. **原链有时效，而且很短。** 各渠道从 2 小时（简梦Z 图片）到 24 小时（火山、简梦F）不等。
   请求记录留 30 天，但里面隔夜的原链多半已经 404 了。
   → **这是抢救工具，不是归档工具**。清单按时间倒序，工具按清单顺序下载，新的先抓。
   清单里 `expiryRisk: "expired"` 的条目失败属于预期。

2. **部分原链带鉴权才能下。** 简梦F、简梦Z 图片、出海营、Skylee 这些渠道的成片下载须带上游密钥，
   而密钥只在服务端、绝不外发。这类条目在清单里标了 `authRequired: true`，
   **直连必然 401/403** → 工具默认跳过并如实计入，不做无谓重试。
   要救这部分只能由服务端代下。

## 用法

```bash
qiji-downloader --manifest 清单.json --out D:\Qiji产物
```

清单从管理端「批量下载」页 → 「导出清单 JSON（给下载器）」拿。

| 选项 | 说明 |
| --- | --- |
| `--concurrency N` | 并发数（默认 4，上限 16） |
| `--retries N` | 每个文件重试次数（默认 2） |
| `--timeout N` | 单文件超时秒数（默认 600 —— 成片可能几百 MB） |
| `--overwrite` | 覆盖已存在的文件（默认跳过，所以重跑只补没下到的） |
| `--include-blocked` | 连「需服务端代下」的也试一下（基本会 401，除非你确认那批不需要鉴权） |
| `--raw-only` | 只下上游原链（`storage=raw`）——它们才是会过期、要抢救的 |
| `--dry-run` | 只列要做什么，不真的下载 |

落盘按清单里的建议路径分目录：`<用户>/<日期>/<步骤>_<日志ID>.<扩展名>`。

## 失败了怎么办

失败清单写在 `<目标目录>/_failed.json`，**格式与输入清单完全相同** ——
直接拿它当 `--manifest` 再跑一次，就只重试失败项：

```bash
qiji-downloader --manifest D:\Qiji产物\_failed.json --out D:\Qiji产物
```

常见失败与含义：

| 现象 | 含义 |
| --- | --- |
| `HTTP 404` / `HTTP 403`，且条目 `expiryRisk=expired` | 原链已过期，救不回来了 |
| `需服务端代下` | 下载须带上游密钥，本工具拿不到 |
| `请求失败：...timed out` | 网络问题，重跑一次通常就好 |

## 实现上的几个保证

- **先写 `.part`，完成才 rename** —— 中断/断网不会留下半截文件冒充成品，
  所以「跳过已存在」判得准，重跑不会漏。
- **流式写入** —— 几百 MB 的成片不会整个进内存。
- **防目录穿越** —— 清单里的路径若含 `..` 段会被剔除，绝不写到目标目录之外。
- **有失败时退出码非 0** —— 方便脚本判断。

## 自己编译

```bash
cd tools/downloader
cargo build --release
```

产物在 `target/release/qiji-downloader.exe`。
