# 实时剪辑模式：原设计与后续演变

核查日期：2026-10-04。范围：只读检索当前源码、项目契约、ACTIVE 和 Git 历史；本文件为审核报告，不修改业务代码或项目记忆。历史记录说明当时的意图与验证状态，不能替代当前设备验收。

## 1. 设计目的：让生成发生在剪辑流程里

**原定位是与资产模式、画布模式并列的第三模式：在时间轴上安排分镜，直接调用 AI 生成，把结果放回既定位置，最后交付可继续编辑的剪映草稿。**

最早完整定稿位于 Git `3b4132960a5aaeee093723868375fb6b962e9b49:CLAUDE.md:699-709`，记录日期为 2026-08-17、第 235 轮。该提交是 229–238 轮合并快照，提交日期 2026-08-19；不能把快照提交日误写成需求提出日。

原文摘录（`3b41329:CLAUDE.md:699`）：

> 用户需求定稿（需求评审三答：轻量顺序预览 / 首版仅导出剪映草稿 / 复合片段+分离音轨放 P1）……最终产物=剪映草稿。

后续最清晰的产品语义保存在第 237 轮源码注释，并已存在于同一历史快照：`3b41329:src/rtc/panel/rtcGenCore.ts:8-18`；当前可读 [rtcGenCore.ts](/D:/kaifa/qiji/qiji/src/rtc/panel/rtcGenCore.ts:8)。

> 轨道是结果的存放位置……重新生成不覆盖原有结果，而是在上方轨道新增一个结果占位……相当于画布模式的节点……轨道就是最好的堆叠方式。

据此提炼的价值判断（属于基于原文的归纳，不冒充当年的逐字需求）：

- 省掉“生成完成后再下载、导入剪辑器、手工对齐原镜头位置”的重复操作。
- 把每次生成的版本放在明确的时间位置与图层上，省掉散落文件和画布节点之间寻找当前版本的工作。
- 复用既有剧本、分集、分镜、角色资产和生成服务，接入“剧本 → AI 分镜/素材 → 粗剪 → 剪映精修”的流程。
- 保留剪映草稿作为交付边界；不是在第一版直接承担独立成片编码器。

## 2. 原始最小闭环与扩展后的独立闭环

### 初版（第 235 轮）

已有分集/分镜 → 按分镜幂等铺占位 → 点占位编辑原文、提示词与参考素材 → 生成故事板/视频 → 结果原位替换 → 拖、裁、分、预览 → 导出剪映草稿 → 剪映继续编辑。

证据：`3b41329:CLAUDE.md:704-709`。当时占位铺设按 `episodeId+shotId` 扫全部轨道去重，已有结果直接成为媒体片段；替换只改媒体身份与源时间窗，**时间轴位置和占用时长不变**。这不是按生成结果自动把后续镜头推开的设计。

### 第 236 轮追加：实时剪辑内部独立完成前置步骤

剧本编辑 → 分集（本地快拆或 LLM）→ 资产拆分 → 资产出图 → 逐集智能推理/拆分分镜 → 占位入轨 → 故事板/视频生成 → 剪辑预览 → 剪映草稿。

`3b41329:CLAUDE.md:694` 明确记录“实时剪辑独立闭环，不依赖资产模式（用户明令）”。实现直接复用 `runPurpose/startInfer/mergeApply/splitEpisodes/attachSplitPresets` 等已有链路；不另造第二套推理、提示词、计费和任务机制。资产出图边界与验证见同文件 `695-698`。

### 第 237–240 轮追加：结果版本与工作台统一

- 生成前先有结果占位，进度在占位上显示；重新生成在上方增加占位，原结果仍在下层。证据：当前 [rtcGenCore.ts](/D:/kaifa/qiji/qiji/src/rtc/panel/rtcGenCore.ts:8)。
- 已落盘 `pendingGens` 与片段 `taskRef` 驱动恢复，替代初版仅有会话回调的机制。证据：`3b41329:src/rtc/panel/placeholderSwap.ts:2-21`，当前 [placeholderSwap.ts](/D:/kaifa/qiji/qiji/src/rtc/panel/placeholderSwap.ts:2)。
- 第 239 轮把占位的提示词/素材/原文/动作/历史移到中栏 AI 工作台，右栏保留模型及参数；播放器常驻，工作台覆盖其上。证据：`9414eda:CLAUDE.md:415-417,696`，对应 `f9d311f`。
- 第 240 轮将 AI 工作台/预览页签收进标题栏；提示词靠近左侧素材；普通图片/视频占位创建或首次绑定时补真实分镜，三模式共享同一分镜数据。证据：`9414eda:CLAUDE.md:681-695`，特别是 `691`；对应提交 `9414eda`。

## 6. 面向本次专项审核的验收基线

按原设计，应优先证明一个可复用的小闭环：**一集、数个分镜、少量媒体，完成占位 → 生成/模拟回包 → 原位落位 → 修改与撤销 → 保存重开 → 导出 → 剪映打开后时间位置和素材引用正确。**

专项再覆盖四类容易造成额外人工或丢失成果的分支：

1. 生成中切集、切项目、关闭重开、删占位、撤销/重做，结果归属是否仍正确。
2. 修改倍速、裁剪、分割、多选跨轨、复合子层之后，源窗口、目标窗口、预览和导出是否一致。
3. 播放头移动、跨镜播放、切工作台/素材、面板换位时，当前工作对象是否清楚、播放是否连续。
4. 草稿文件自包含、材料去重、字幕/转场/关键帧/复合是否实际被目标剪映版本识别。

本报告没有启动付费生成、没有操作真实项目、没有完成设备或剪映全链路验收；这些是审核应查的交付条件。
