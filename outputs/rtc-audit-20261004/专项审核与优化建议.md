## 优先问题

以下 P1 表示建议在下一轮交付前优先修复的用户流程问题；P2 表示次一级功能缺陷。没有将代码体积、命名偏好或缺测试本身当作缺陷。

### R1 · P1：素材准备中切项目，归属会改变

**触发**：在 A 项目导入大素材，或提交带参考素材的故事板/视频，准备尚未完成时切到 B。

- 导入路径先等待文件哈希，再调用本地落盘；等待前没有冻结项目身份。实际导入入口 [RtcAssetPanel.tsx:307](D:/kaifa/qiji/qiji/src/rtc/RtcAssetPanel.tsx:307) 调用 [nodeUpload.ts:59](D:/kaifa/qiji/qiji/src/canvas/nodeUpload.ts:59)，后者继续用当前 store 登记素材。
- 生成路径在 `ensurePublicUrl` 之后才调用当前项目的队列，未核对最初项目：[shotGenActions.ts:105](D:/kaifa/qiji/qiji/src/rtc/panel/shotGenActions.ts:105)、[shotGenActions.ts:162](D:/kaifa/qiji/qiji/src/rtc/panel/shotGenActions.ts:162)、[generationQueue.ts:358](D:/kaifa/qiji/qiji/src/services/generationQueue.ts:358)。
- 已隔离复现 A 发起、B 登记/提交。复制项目保留同 ID 时可能关联到 B 对应镜头；不同 ID 时旧请求也失去正确目标。没有声称发生过真实扣费或真实项目串写。

**建议**：点击时冻结项目实例、分集、分镜/片段和输入快照；准备与登记复用已有 `shouldContinue` 等归属守卫，提交前再次核对。目标失效时停止提交，并给出明确状态。

### R2 · P1：素材准备期间重复点击会产生多个请求

**触发**：参考素材公网化较慢时，再点一次生成。

[工作台按钮](D:/kaifa/qiji/qiji/src/rtc/panel/RtcShotAiWorkbench.tsx:332) 只根据 `pendingGens` 禁用；pending 在等待素材完成后才创建。真实队列 [generationQueue.ts:358](D:/kaifa/qiji/qiji/src/services/generationQueue.ts:358) 每次新建 ID，没有按当前操作目标去重。隔离调用证明同一分镜/占位产生两次提交、两次绑定；真实收费尚未执行。

**影响**：用户本意一次操作，可能产生多笔费用，且一个占位只保留一个当前监听，另一结果需要从历史找回。

**建议**：第一处异步等待前建立本次操作的准备锁，并显示“准备中”；持续到受理完成/失败后释放。锁按项目和操作目标管理，保留用户显式创建多个版本的能力。

### R3 · P1：重开停留另一分集，已完成结果无法自动入轨

**触发**：A 集提交 → 切 B 集并保存关闭 → 重开仍在 B → A 先完成 → 返回 A。

[placeholderSwap.ts:214](D:/kaifa/qiji/qiji/src/rtc/panel/placeholderSwap.ts:214) 只扫描当前 `rtcStore.doc`，而生成队列会恢复全项目任务。A 的结果进入分镜历史并销账后，没有已挂上的占位监听；再进 A 时会被判为“结果没能自动落位”，要求重新生成。该路径已用实际对账模块隔离复现。

**建议**：恢复时覆盖全部分集档位，保留请求到具体结果/片段的投递凭据，直到时间轴写入并确认保存后再清理。已有结果应优先恢复入轨，避免让用户再次付费生成。

### R4 · P1：视频与字幕共同复合后，内容消失

**触发**：选中视频和字幕，创建复合片段。

[rtcCompound.ts:112](D:/kaifa/qiji/qiji/src/lib/rtcCompound.ts:112) 以显示最上方轨为宿主，可能选中字幕轨；预览与草稿导出仍按宿主轨类型解释内容。复现中复合前视频/字幕各 1 个，复合后可见项均为 0，导出轨道为 0。只有该组内容时导出服务会报无可导出片段；另有其它内容时可能跳过此组继续导出。

**建议**：复合片段明确自身媒体语义并选择合法宿主；预览、解散与导出使用同一解释。验收必须包括视频+字幕，以及图像、音频混合选择。

### R5 · P1：分割或左裁带关键帧的片段，动画被重置

[splitSegment](D:/kaifa/qiji/qiji/src/lib/rtcOps.ts:511) 将原关键帧直接复制到两半；[trimSegment](D:/kaifa/qiji/qiji/src/lib/rtcOps.ts:399) 左裁没有同步重映射关键帧。关键帧时间相对片段起点，起点变化后必须调整。

隔离样例：10 秒动画从 x=0 到 x=1，在第 5 秒分割；原绝对第 6 秒应为 x=0.6，分割后变成 x=0.1。左裁 5 秒也有相同结果。位置、透明度和音量等共用时间模型的通道均需核对。

**建议**：复用已有定格操作采用的关键帧分账逻辑，右段时间归零并补切点采样；左裁也平移关键帧。以编辑前后同一原始时刻效果一致为验收条件。

### R6 · P2：进入复合片段后，部分属性操作静默失效

子层读取使用 `activeRtcDoc`，但 [rtcSegUtils.ts:32](D:/kaifa/qiji/qiji/src/rtc/panel/rtcSegUtils.ts:32)、[RtcTimeFields.tsx:94](D:/kaifa/qiji/qiji/src/rtc/panel/RtcTimeFields.tsx:94)、[RtcTransformProps.tsx:322](D:/kaifa/qiji/qiji/src/rtc/panel/RtcTransformProps.tsx:322) 等仍提交主文档，找不到子片段就返回原值。

**影响**：子层音量、静音、转场、时间和画面变换等入口看起来可编辑，但部分写入未发生；倍速已经使用 `commitActive`，导致行为不一致。

**建议**：编辑当前层的动作统一通过 `commitActive`，直接操作根文档的动作保持明确。逐项验证修改、撤销、保存重开。

### R7 · P1：复合导出丢失编辑信息，用户看不到提醒内容

[jianyingCompound.ts:218](D:/kaifa/qiji/qiji/src/lib/jianyingCompound.ts:218) 跳过子层字幕，`:262` 明确放弃画面变换；关键帧、裁剪、转场和子轨静音等也没有完整映射。隔离构建证明缩放/位移/旋转恢复默认、关键帧字段缺失、轨道静音属性未写入。

这部分源码标注了 P0 限制，是**现有能力缺口**，没有证据称为近期引入的回归。但它直接影响交给剪映继续编辑的核心交付。工具条 [RtcToolbar.tsx:219](D:/kaifa/qiji/qiji/src/rtc/RtcToolbar.tsx:219) 仅展示“几条提醒”，没有明细入口，员工难以知道损失了什么。

**建议**：先让导出前列出具体受影响片段与属性，明确表达有损结果；再让主层/子层共用尽可能相同的序列化逻辑。剪映实机打开后对照字幕、构图、关键帧、静音与时间位置，不能以生成 JSON 成功代替验收。

### R8 · P1：两个窗口编辑不同分集也可能覆盖对方时间轴

[projectSyncCore.ts:46](D:/kaifa/qiji/qiji/src/lib/projectSyncCore.ts:46) 把 `rtcDocs` 作为整表广播；接收方 [projectSync.ts:281](D:/kaifa/qiji/qiji/src/services/projectSync.ts:281) 浅层覆盖。两个窗口在互相收到广播前分别改 ep1/ep2，后到快照会把另一集恢复旧值。代码注释承认了该边界，但“不同分集分工”本身无法避免整表覆盖。

已用实际字段差异函数及接收浅合并模型复现：预期两个分集都是新值，实际第一集变回旧值。**这是同步算法隔离复现，尚非真实双窗口验收。**

**建议**：按分集 ID 广播/合并时间轴，并为同分集冲突定义版本检查；过渡期至少明确单编辑者，不能默默接受覆盖。

### R9 · P2：显式生成规格和参考素材仍有静默变化

- 时长下拉 [RtcShotAiWorkbench.tsx:313](D:/kaifa/qiji/qiji/src/rtc/panel/RtcShotAiWorkbench.tsx:313) 和提交 [shotGenActions.ts:197](D:/kaifa/qiji/qiji/src/rtc/panel/shotGenActions.ts:197) 先执行固定 4–15 秒夹钳，再匹配 catalog。实际函数复现：catalog 允许 `[10,15,20]`，选择 20 最终得到 15。此样例证明能力条件下存在缺陷，不声称已核查当前生产具体模型。
- 显式开启“带故事板”后，故事板无法转成公网地址时仍可提交，并省略 `firstFrameUrl`：[shotGenActions.ts:162](D:/kaifa/qiji/qiji/src/rtc/panel/shotGenActions.ts:162)。已隔离复现，没有错误提示。

**建议**：仅为缺失值补默认；保留显式时长与规格，沿用后台能力配置及上游真实报错。用户明确选择的素材准备失败则明确停止请求，不静默删除参考。该方向与当前 CODEX 及项目合作伙伴技能一致。

## 后续优化与待验证项

- **版本轨道落点**：`pickResultTrack` 使用数组小下标代表“上方”，与当前显示序相反；已有上层结果再次生成时可能放到较低层。应按显示序复核并统一。初始主轨新建有防抢主轨的补偿，不能笼统说所有重新生成都会放错。
- **复合内转场**：主层有渐变叠加层，复合内部采样缺少同等转场层；纯函数已复现。应纳入复合预览/导出一致性修复。
- **锁轨保护**：先选片段再锁轨，删除、变速等入口与拖拽保护不一致；详见编辑报告，仍需实际 UI 手势验收。
- **声音预览**：界面可设置大于 1 的音量，预览被夹到 1，导出保留增益；需要明确预览能力并验证混音，不能当作已测量的音质问题。
- **运行态与性能**：`patchSilent` 只免撤销，仍通过 `setRtcEpisodeDoc` 标脏和广播整表。建议将频繁进度与持久化文档分离，保留任务身份与关键终态；本轮未测量长时间轴帧率或内存，故不宣称已经证明卡顿来源。
- **存量自由占位草稿**：localStorage 的跨设备/保留期边界仍存在，但普通新占位已升级成真实分镜，不能将它概括为全部 RTC 提示词都不随项目保存。
- **子文档任务回填**：sink 只查顶层已确认；当前普通占位禁止组合，子层重新生成又会在更早入口失败，未将其列为已证可触发的付费结果丢失。修子层生成入口时需同步修回填扫描。

已排除一个初步猜测：官方素材认证在统一 managedAdapter 继续准备，不能仅凭 RTC 动作里组装 URL 就认定绕过官方素材处理。
