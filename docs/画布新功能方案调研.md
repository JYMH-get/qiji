# 画布新功能方案调研（3D 导演台 / 深度图 / 转视角 / 720°全景 / 图片标注）

> 调研日期：2026-08-02。仅方案调研，未实现。所有 stars / license 经 GitHub 实测核实。
> 共同约束：Tauri 2 + React 18 + WebView2 客户端（@xyflow/react 画布）；服务端 Fastify 网关 + 聚合 AI 上游（已有即梦/Gemini/OpenAI 兼容等渠道）；无自建 GPU；用户在中国大陆；商用闭源产品（license 是硬约束）。

## 总览（推荐路线一句话版）

| 功能 | 推荐路线 | 新增基建 | 工作量级 |
|---|---|---|---|
| ① 图片标注 | react-konva + perfect-freehand 自建轻量标注层，嵌进现有灯箱 | 无 | ~1.5–2 周 |
| ② 图片转黑白深度 | 客户端 transformers.js + Depth Anything V2-**Small** ONNX 本地推理（WebGPU→WASM 降级） | 模型文件 19–27MB 打包/OSS 下发 | ~1 周 |
| ③ 图片转视角 | 走现有网关的图像编辑模型直出（即梦 SeedEdit / nano-banana 双路）+ 视角预设按钮 | 无（prompt 模板 + 路由） | ~1–2 周 |
| ④ 720° 全景 | 生成走网关（图生全景/FLUX 全景 LoRA 上游）；查看用 Photo Sphere Viewer；机位截图 py360convert | 查看器依赖 + 可选小 Python 工具 | ~2 周 |
| ⑤ 3D 导演台 | r3f + drei + three-vrm 自研，移植 open-pose-editor（MIT）摆姿代码加速 | three 全家桶 | MVP ~4 人周（五项里最大） |

落地顺序建议：**① → ② → ③ → ④ → ⑤**（按 投入产出比 与 依赖关系：标注/深度零上游依赖最快见效；转视角只加 prompt 模板；全景需选定生成上游；导演台是独立大件）。

## ① 图片标注

**主推：react-konva + perfect-freehand 自建**（全 MIT，合计 ~94KB gzip）。

- konva 14.7k★ MIT + react-konva 6.4k★ MIT（声明式 JSX，与 React 18 同构）+ perfect-freehand 5.6k★ MIT（1.5KB 压感笔迹算法）。
- 能力全命中：Konva.Arrow 箭头 / Rect+Transformer 框选 / Text 文字（叠 HTML textarea 编辑）/ 自由圈选闭合填充。
- **导出三件套是 Layer 架构的天然优势**：合成 PNG=`stage.toDataURL`；纯标注层=`annotationLayer.toDataURL`；**黑白 mask=同一份矢量 state 在离屏 Stage 黑底白绘重渲**（几十行代码，封装库都做不顺这点）。
- 生产级先例：InvokeAI 的 inpaint 画布（Apache-2.0）就是 React+Konva，可参考架构。
- 集成形态：**灯箱（Lightbox）内加「标注」编辑态**，不做独立标注节点；标注矢量 JSON 按图片存进节点 data，缩略图叠只读小徽标；确认时导出 合成图（发多模态）+ mask（发局部重绘）+ 矢量 JSON（可再编辑）。
- 多模态「圈选+指令」实践：Set-of-Mark（arXiv:2310.11441）与红圈论文（arXiv:2304.06712）——**给 VLM 的合成图默认用红色粗闭合圈**效果最好；但**发给图像编辑/inpaint 模型时要用干净原图+mask 双通道**（红圈会被当画面内容画进去）。
- 排除项：**tldraw 已非开源**（生产必须买 license key，商业版约 $6,000/年，直接出局）；markerjs3 是 Linkware（要求运行时署名链接）；Excalidraw 344KB 过重且 mask 导出困难；Annotorious/react-image-annotate 是 ML 打标品类，错位。

## ② 图片转黑白深度

**主推：客户端本地推理**——transformers.js v3 + `onnx-community/depth-anything-v2-small`（int8 约 27MB / q4f16 约 19MB）。

- **License 是最大的坑：Depth Anything V2 只有 Small 是 Apache-2.0 可商用，Base/Large 是 CC-BY-NC 不可商用，效果再好也不能换**。可商用备选：Depth Anything 3（字节 2025.11，Apache-2.0）、MiDaS/ZoeDepth（MIT）。Apple Depth Pro license 禁商用，排除；Marigold 是扩散模型分钟级太慢，排除。
- 性能量级（Small 518×518）：WebGPU（含核显）200–500ms；纯 WASM CPU 1–3s（加进度条可接受）。WebView2 的 WebGPU 可用 Tauri `additionalBrowserArgs` 注入 `--enable-features=WebGPU` 开启，代码里做 webgpu→wasm 自动降级。
- **模型不能运行时连 huggingface.co（被墙）**：打进 Tauri 安装包或从自有 OSS 下发，`env.localModelPath` 指本地。
- 兜底：Fastify 网关内嵌 onnxruntime-node 跑同一个 ONNX（transformers.js Node 版 ~50 行），老机器/模型未下发时走服务端；客户端与服务端用**同一模型文件 + 同一前处理**保证出图一致。
- 不推荐：Replicate（$0.0026/次）/fal.ai 等海外 API（大陆连通性差）；硅基流动无深度模型。
- 参考 repo：[DepthAnything-on-Browser](https://github.com/akbartus/DepthAnything-on-Browser)（MIT，含 WASM/WebGPU demo + three.js 点云 2.5D 视差参考）、[Depth-Anything-ONNX](https://github.com/fabio-sim/Depth-Anything-ONNX)、[transformers.js WebGPU 深度示例](https://github.com/huggingface/transformers.js/tree/v3/examples/webgpu-video-depth-estimation)。

## ③ 图片转视角

**主推：图像编辑模型直出（走现有网关，零新基建）**，做「视角预设」UI（左/右侧、3/4 侧、背面、俯/仰视等 8 档），网关侧每档 prompt 模板 + 模型路由，一次出 2–4 张候选让用户挑。

- 双主力：**即梦 SeedEdit 3.0**（官方点名「视角与光线转换」是优势场景，已接入、大陆合规）+ **Gemini 2.5 Flash Image / nano-banana**（角色一致性公认最强，已有 Gemini 上游，~$0.039/张）。
- 低成本档：**Qwen-Image-Edit 2509**（Apache-2.0，阿里百炼 ~¥0.2–0.3/张）+ 社区多角度 LoRA [dx8152/Qwen-Edit-2509-Multiple-angles](https://huggingface.co/dx8152/Qwen-Edit-2509-Multiple-angles)（离散档位：水平 ±45°/±90°、俯仰 -30°~60°、推拉——注意百炼官方 API 不带 LoRA，档位控制需 WaveSpeed/Replicate 托管版或纯 prompt）。
- GPT-Image 不推荐作主力（身份漂移是公认短板）。
- **共同弱项：转全背面（180°）靠脑补**——UI 上把「背面」档标注需用户校对。
- 二期：**Seedance 环绕运镜 + ffmpeg 抽帧**做「角色转身图集」批量功能（几何一致性好但贵且慢，产出可回填为角色一致性参考图）。
- 三期可选：**腾讯云混元生3D API**（大陆直连、积分计费、Hunyuan3D-2.1 社区 license 可商用）对重点角色一次建模 → three.js 任意取角 → 截图过编辑模型「回漫画风」；几何一致性唯一有硬保证的路线，但有「手办感」风险。
- 自部署开源多视角扩散模型（Zero123++/SV3D/SEVA/Era3D 等）**现阶段全部排除**：无 GPU、显存 16–43GB，且多数权重 license 卡商用（Zero123++ 权重 CC-BY-NC、SEVA 非商用、Era3D AGPL）。未来私有化再看 MV-Adapter（Apache-2.0，1.3k★）与 CharacterGen（Apache-2.0，专做动漫角色）。

## ④ 场景 720° 全景

**生成端三档并存：**

1. 首选走现有网关：上游若有 **FLUX.1-dev + LoRA** 能力挂 [FLUX Equirectangular LoRA](https://civitai.com/models/735980)（2:1，1408×704–2048×1024，注意 FLUX.1-dev 商用授权需确认上游已获）；或接 **fal.ai `hunyuan_world`**（图生全景，正好覆盖「概念图→全景」）。接缝不闭环时服务端做「左右缝 inpaint」兜底后处理。
2. 质量/省心档：**Blockade Labs Skybox API**（原生 8K 无缝 equirect + 深度图，Business $112/月起完整 API；境外服务由网关中转，客户端无感）。
3. 自建档（调用量大再说）：腾讯 [HunyuanWorld-1.0](https://github.com/Tencent-Hunyuan/HunyuanWorld-1.0)（~2.9k★，社区 license 需评估；lite 可跑 4090，文/图双入口，1920×960）或 [DiT360](https://github.com/Insta360-Research-Team/DiT360)（MIT 但需 ~37GB 显存）。通义万相/即梦暂无官方全景 API。

**查看端：** [Photo Sphere Viewer](https://github.com/mistic100/Photo-Sphere-Viewer)（2.3k★ MIT 活跃）+ [react-photo-sphere-viewer](https://github.com/Elius94/react-photo-sphere-viewer) 封装。**画布节点缩略图用静态图（不跑 WebGL），点击弹窗再挂查看器**，关闭时 `dispose()`（WebView2 有 WebGL context 数上限）。Marzipano 已归档，排除。后续要在球内叠分镜框可换 r3f 自绘球体（30 行）。

**机位→分镜图（贴合「选机位/定分镜」语义）：** 用户在查看器转到目标机位 → 读 `yaw/pitch/fov` → 发服务端 [py360convert](https://github.com/sunset1995/py360convert) `e2p` 重采样出**全分辨率透视图**落库为分镜参考资产；机位是结构化数据可随时重出图。Node 侧无成熟等价库，旁挂小 Python 脚本或 wasm 自实现。

## ⑤ 画布 3D 导演台

**主推路线 C（混合）：r3f 自研主干 + 移植开源摆姿代码加速。**

- 技术栈没有第二选项：**three.js（114k★ MIT）+ @react-three/fiber（31.6k★ MIT）+ drei（9.8k★ MIT，OrbitControls/TransformControls/PivotControls 现成）+ [pixiv/three-vrm](https://github.com/pixiv/three-vrm)（2k★ MIT，pixiv 官方活跃维护，VRM 人偶标准 humanoid 骨骼 → 姿势预设可跨角色复用）**。r3f `<Canvas>` 直接挂画布节点双击弹出的全屏抽屉/独立窗口，不需要 iframe。
- 核心参考项目：[ZhUyU1997/open-pose-editor](https://github.com/ZhUyU1997/open-pose-editor)（956★ MIT，3D 火柴人摆姿 + **一键导出 openpose/depth/normal/canny**，停更 2.5 年但可用；骨骼操纵代码可 MIT 移植）+ [comfyui-vrm-pose-editor](https://github.com/ketle-man/comfyui-vrm-pose-editor)（MIT，three-vrm 摆姿编辑器参考实现，核心声明零 ComfyUI 依赖）。
- 条件图导出在 three.js 里都是低成本操作：depth=`MeshDepthMaterial` 一行切换、normal=`MeshNormalMaterial`、openpose=骨骼关节 `project()` 到屏幕坐标绘 COCO18 线条（1–2 天）、相机参数 fov/position/quaternion 可序列化（留给未来视频运镜控制）。一次渲染四份：美术截图 + openpose + depth + normal + 相机 JSON，直接塞进现有生图请求。
- 人偶资源：VRoid Hub（按可商用筛选）/ VRoid Studio 免费捏人出 VRM；默认占位人偶用 Quaternius/Kenney 的 CC0 低模（可随应用分发）；Mixamo 模型不可再分发（只能引导用户自取）。
- **排除项：mannequin.js（GPL-3.0 传染）、posex（无 license）、Babylon.js（React 绑定与 vrm/openpose 生态错位）、fkunn1326/openpose-editor（archived）**。
- 分期：一期（~4 人周）场景框架 + 火柴人/低模摆姿 + 相机 + openpose/depth/截图导出，已可闭环 ControlNet 生图控制；二期接 VRM 加载 + 姿势预设库 + 真实角色参考图。最大风险是骨骼拖拽交互手感，需要打磨（手指精调先用姿势预设库绕过）。

## 共同工程注意

1. **License 红线清单（勿踩）**：Depth Anything V2 Base/Large（CC-BY-NC）、tldraw（专有）、mannequin.js/Era3D（GPL/AGPL）、posex（无 license）、SEVA/Stable Zero123/Apple Depth Pro（非商用）、FLUX.1-dev 权重（自部署非商用，走已授权上游没事）。
2. **大陆网络**：一切模型文件（ONNX/LoRA/VRM 示例）走自有 OSS 或 hf-mirror/ModelScope 下发，客户端绝不直连 huggingface.co/Civitai；海外 API（Blockade/fal/WaveSpeed）一律经 Fastify 网关中转（与现有架构一致）。
3. **WebView2**：WebGPU 需 `additionalBrowserArgs` 开启并做降级；WebGL context 有数量上限，弹窗类 3D 组件（全景查看器/导演台）关闭必须 dispose；无 GPU/远程桌面会回退软渲染，需检测（`WEBGL_debug_renderer_info`）。
4. **与现有架构的契合**：②③④ 的生成类调用都应走既有 `runPurpose → /v1/generate` 唯一请求路径（新增 purpose + 服务端模板/翻译器），计费/退款/请求记录自动继承；①⑤ 是纯客户端功能，产物（标注合成图/mask/导演台条件图）经 `uploadAsset` 落 OSS 后作为垫图进生成请求。
