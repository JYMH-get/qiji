# 渠道节点部署手册（relay 模式）

> 面向：想独立部署的渠道商（以及给他们做支持的源站运营）。
> 对应：商业化改造 P3（docs/商业化改造方案.md §5），2026-08-09 上线。

## 0. 一句话

把**同一套服务端**装到你自己的服务器上、配三个环境变量，就是一个「渠道节点」：
用户在你的节点上注册、积分由你本地发行；生成与素材全部由节点转发源站，
按**平台统一价**从你在源站的积分池实扣——池余额就是你能提供的服务上限。

节点**不需要**配置 OSS，也**不接触**任何上游 AI 渠道密钥。

## 1. 前置条件

| 项 | 说明 |
|---|---|
| 服务器 | 任意可跑 Node.js 24+ 的 Linux/Windows 服务器；需公网可达（客户端要连它） |
| 节点密钥 | `ank-` 开头；源站管理端「渠道商详情 → 渠道节点」生成，或渠道商门户「渠道节点」页自助生成 |
| 源站地址 | 源站的公网地址（客户端素材直链/302 兜底也会指向源站，**源站必须公网可达**） |
| 积分池 | 你在源站的积分余额——转发消耗从这里扣，为 0 时全部生成请求 402 |

## 2. 部署步骤

```bash
# ① 拿到服务端代码（与源站同一套）
cd server && npm i

# ② 配置 .env
PORT=8787
ADMIN_TOKEN=换成你自己的强口令
NODE_ROLE=relay
SOURCE_URL=https://源站地址
SOURCE_NODE_KEY=ank-xxxxxxxx

# ③ 启动
npm run dev        # 或用 pm2/systemd 常驻
```

启动日志出现 `Qiji 渠道节点（relay）已启动` 即角色正确。

## 3. 对接自检清单

1. 打开节点 `/admin`（用你的 ADMIN_TOKEN 登录）——顶部「**源站连接**」条：
   - `已连通` + 显示你的商名与**积分池余额** → 对接成功；
   - `未连通` → 核对 SOURCE_URL 可达、SOURCE_NODE_KEY 未被重置、你的商账号未被源站停用。
2. 节点管理端「注册与安全」配置 SMTP → 客户端指向节点地址注册一个测试账号。
3. 节点管理端「用户管理」给测试账号充点积分（或发**本地兑换码**）。
4. 客户端用测试账号跑一次生成：
   - 成功 → 节点「请求记录」出现一条 success，用户积分按平台价实扣；
   - 源站侧：该商范围的请求记录出现同一条（金额相同）。
5. 节点管理端可见页 = 用户/兑换码/团队/统计/共享素材/请求记录/注册与安全
   （模型/渠道/模板/预设/存储等源站专属页自动隐藏，对应 API 也已 403）。

## 4. 计费与对账

- **金额恒等**：每笔生成，节点按**源站回传的实扣金额**扣本地用户，源站按同额扣你的池。
  对账 = 节点「请求记录」合计 vs 源站管理端「渠道商详情 → 请求记录」合计。
- **失败退款两侧同退**：任务失败源站自动退池；节点在轮询/定时清扫（每 10 分钟）见到失败后
  退本地用户。客户端崩溃没人轮询的单，最迟由清扫兜底（源站过期 72h 后按中断退款）。
- **池扣穿**：池余额不足时所有转发请求 402，终端用户看到的是中性文案
  「服务暂不可用，请联系你的服务商」；你在节点 `/admin` 顶部随时能看到池余额。
- **本地积分是你自主发行的**（信任边界，方案 §5.3）：想发多少发多少，源站不管——
  守门员只有积分池。本地发多了、池不够扣，是你自己的商务问题。
- **坏账告警**：极端并发下本地用户余额可能不够镜像实扣（预估与实扣有差时），节点会扣到 0
  并在日志打 `[relay] 本地余额不足实扣` 告警——差额是你的坏账，出现频繁就调高预收积分门槛。

## 5. 边界与注意

- **重置节点密钥 = 旧密钥立即失效**：先改节点 `.env` 再重置，或重置后立刻更新并重启节点。
- 节点用户的素材存储在源站（OSS/台账都在源站）；引用上报已透传，**收藏（永久保留）**同样透传源站。
- 节点暂不支持**扩容卡**（400 明确提示）；收藏配额=源站全局默认档。
- 参考视频按秒计费的模型：节点侧预估价不含视频时长加权，**实扣以源站为准**（预检可能偏低，属预期）。
- 节点本地的「请求记录」只有 ①请求 ②响应 两段（上游 ③④ 段只在源站）。
- 团队/共享素材库是**节点本地**的体系，与源站互不相通。
- 源站升级后节点也要同步升级（同一套代码，协议同步演进）。

## 6. 源站运营侧速查

- 生成/重置密钥：管理端「渠道商 → 详情 → 渠道节点」或商在门户「渠道节点」页自助。
- 看节点消耗：管理端「请求记录」范围切到该商（节点转发的记录 ownerId=该商，
  userId 带 `nu:` 前缀=节点本地用户留痕，userName=节点用户昵称）。
- 停用该商 = 节点全部请求 401（密钥仍在但商 disabled）。
- 该商积分管理照旧：「渠道商」页分发/扣回。
