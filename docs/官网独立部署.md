# Qiji 官网独立部署

官网使用静态 HTML 和图片，部署到单独的网站目录。业务服务继续提供 `/admin`、`/agent`、`/v1/*`、素材接口和健康检查；不再提供公开的 `/` 和 `/site-assets/*`。

## 内容与发布

- 官网源码：`website/template/`；静态渲染：`website/render.ts`。
- 内容草稿仍由业务管理后台的「网页管理」维护，保存在原 `server/data/site.json`。
- 「保存内容」只保存草稿；「保存并预览」和「保存并导出部署包」先保存当前内容，再生成对应快照。
- 导出的 `qiji-website.zip` 只包含 `index.html` 和 `site-assets/`。不含数据库、用户资料、密钥、后台页面或 Node.js 服务。
- 更新公告、下载链接、图片、备案号或站点开关后，须重新导出并部署。关闭开关导出的是维护页，也须部署后才改变线上展示。
- 安装包、已上传的官网图片继续使用既有对象存储链接。静态官网不依赖业务 API；这些外链资源仍依赖各自的存储服务。
- 自动更新发布与官网下载相互独立，现有客户端更新 feed、签名和发布流程保持不变。

## 从后台导出

1. 在业务后台打开「网页管理」，编辑内容。
2. 点击「保存并预览」检查页面，或点击「保存并导出部署包」下载 ZIP。
3. 在官网服务器的 1Panel 中创建**静态网站**，绑定准备使用的官网域名。
4. 把 ZIP 解压到该网站的根目录，确保根目录直接包含 `index.html`，而不是多套一层文件夹。发布前保留旧静态目录以便回退。
5. 配置官网 HTTPS，检查首页、功能、下载、加入我们、更新记录、图片及备案链接。

官网站点无需反向代理到业务端口，也无需开放业务管理接口。HTML 建议设置 `Cache-Control: no-cache`，替换包后刷新核对新内容。

备案审核期间可完成本地准备和预览；公网开站按接入商审核要求执行。备案号获批后填入真实编号，导出页面会链接到工信部查询系统；留空时不展示虚构编号。

## 从本地构建

需要 Node.js 24 和项目现有 npm 依赖，命令在仓库根目录执行：

```powershell
npm run site:build -- --config server/data/site.json
```

必须显式指定配置文件，构建不会加载服务端或改写业务数据。默认输出到独立的 `outputs/website-*` 目录；也可用 `--out` 指定一个尚不存在的输出目录。输出目录与 ZIP 路径以命令实际结果为准。

从本地配置生成的包只代表该配置快照。正式发布应从线上后台导出，确保包含线上实际维护的下载地址和公告。

## 服务端更新顺序

先准备并验收独立官网，再更新业务服务端，以免先移除旧首页造成官网中断。备案尚未允许公网开站时，先完成本地验证，不提前切换。

服务端镜像仍携带 `website/render.ts` 和 `website/template/`，供鉴权后的预览、导出使用；模板不通过公开路由提供。原有服务端打包脚本已包含这些文件，不能只上传 `server/` 而遗漏 `website/`。

原地址的 `/` 与 `/site-assets/*` 更新后返回 404；`/admin`、`/agent`、`/v1/*`、`/health`、`/ready` 保持原用途。此次不更换客户端 API 地址，不调整业务服务器端口或反向代理配置。

## 验证

```powershell
npm run site:test
npm --prefix server run typecheck
```

官网专项测试使用隔离数据和模拟网络，验证管理员鉴权、渠道节点限制、静态包内容、配置注入与独立访问。导出只表示静态包生成成功，不表示已上传或已部署。
